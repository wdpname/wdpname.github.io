1. sql基础

1. 数据库三大范式

第一范式 保证每列属性都是不可再分的

第二范式 在第一范式的基础上，主要是对联合主键而言，除主键外的所有列属性必须与整个主键有关，而不是与主键的某一部分有关。

第三范式 在第二范式的基础上，要求非主键属性必须与主键直接相关，而不能间接相关。

2. 怎么连表查询

内连接 inner join 返回匹配的行

左外连接 left join 返回左表中的所有行，未匹配的右表列会包含null

右外连接 right join 返回右表中的所有行，未匹配的左表列会包含null

全外连接 lfet join union right join；

3. 怎么避免重复插入数据

使用 unique列约束

使用 insert ingore 当表中存在相同的数据时，这条插入sql直接作废

4. char和varchar有什么区别

char代表长度固定的字符串类型，适用于短字符串存储。

varchar代表长度可变的字符串类型，适用于用户数的的文本等。

5. Text数据类型可以无限大吗

mysql中3种text类型的最大长度如下

TEXT：65535 bytes ~ 64Kb 2^16 2字节

MEDIUMTEXT: 16,777,215 bytes ~ 16Mb 2^24 3字节

LONGTEXT：4,294,964,295 bytes ~ 4Gb 2^32 4字节

6. 什么是外键约束

用来维护表与表之间的关系，确保数据的完整性和一致性。用foreign key references来定义表的外键； 比如

这里的例子，表示该表的course_id属性是这个表的外键，对应courses表的id属性

7. 关键字in和exists

都是用来处理子查询的。

in用来检查该列属性 是否包含在右边的子查询的结果集中。

exist用来判断子查询是否有结果，如果有结果，返回true，否则返回false；

8. mysql中的一些基本函数

字符串函数

concat， length， substring， replace。

数值函数

abs， power，

日期和时间函数

now， curdate

聚合函数

count，sum，avg，max，min。

count不对null计数。

2. 存储引擎

1. 执行一条sql请求的过程是什么

首先建立连接，查询缓存，如果有缓存，那么就直接返回查询结果。如果没有缓存，那么通过解析器解析sql语句，生成语法树，最后执行sql。

2. mysql的引擎

默认mysql引擎是innoDB，它支持事务、行级锁、外键约束。适用于高并发场景

myisam,它不支持事务、行级锁、外键约束等。具有较低的内存消耗。

3. MySQL为什么InnoDB是默认引擎？

因为innodb具有事务支持，并发性能高，数据恢复（通过redolog日志实现数据恢复）等优势。

4. innodb与myisam的区别

是否支持事务

锁粒度，innodb支持行级锁，myisam只支持表锁

innodb引擎是聚簇索引，数据和索引放在一起，而myisam引擎是非聚簇索引，数据和索引是独立的。

数据管理里，数据文件大体分成哪几种数据文件

db.opt 存储当前数据库的默认字符集和字符校验规则

表名.frm 存储这个表的结构定义，元数据

表名.ibd 存储这个表的数据

3. 索引

1. 索引有什么好处

提高查找效率

2. 有哪些索引

按物理存储分类：有 聚簇索引、二级索引

按字段个数分类：有 单列索引、联合索引

按字段特性分类：有 主键索引、唯一索引、普通索引、前缀索引

按数据结构分类：b+树索引，hash索引，全文索引

主键索引和唯一索引的区别在于索引列是否支持包含null，对于主键索引不支持包含null，而唯一索引支持包含null

普通索引 既不要求索引列为主键，也不要求索引列为唯一字段。

前缀索引：主要针对字符类型的字段。比如 char， varchar等

3，聚簇索引和非聚簇索引的区别

聚簇索引主要是主键创建的，而非聚簇索引主要是非主键创建的。

聚簇索引的效率更高，而非聚簇索引一般需要进行两次搜索。

聚簇索引的叶子节点包含了完整的记录行，而非聚簇索引的叶子节点只包含主键值。

4. 什么字段适合当作主键

字段唯一且不为空

字段具有自增的特性

5. 索引是怎么实现的

使用b+树来实现索引。

b+树是一个多叉树，b+树存储千万级的数据只需3-4层高度，如果将读取一个节点当作一次磁盘io，那么查询一个数据只需要3-4次io操作。

6. B+树的特性是什么

所有叶子节点都在同一层。这样能够保证数据的查询都具有相同的时延，提高了查询效率。

非叶子节点存储键值。非叶子节点存储主键值和指向子节点的指针，不存储数据。

叶子节点存储数据记录，这意味着每次都要查询到叶子节点才能找到所需的数据。

自平衡，这说明在在进行插入删除操作时，会自适应调整书的高度，从而保持良好的搜索性能。

7. b+树和b树的区别

b+树非叶子节点只存储索引信息，而b树非叶子节点和叶子节点都存储数据和索引信息。

b+树叶子节点存储完整数据。

b+树的叶子节点由链表相连，而b树的叶子节点没有链表相连。

b+树支持范围查找，b+树不支持。

b+树查找性能稳点，而b树查找性能不稳定。

8. mysql为什么用b+树结构？和其他结构比的优点

和b树相比，单个节点b+树存储的信息更多，从而有更少的磁盘io，相比效率更高。另外，b+树支持范围查找。

和二叉树相比，b+树磁盘io次数更少，搜索效率更高。在数据量很大的情况，这种优势更加明显。

和hash相比，虽然hash在等值查询速度最快，但是b+树的范围查找应用更加广泛。

9. 联合索引的实现原理

将多个列属性组合作为一个索引，这个索引称为联合索引。

10. 创建联合索引需要注意什么

要注意联合索引创建的字段顺序。

要将区分度大的字段排在联合索引的前面。 区分度 = 不同值个数/总行数 比如 性别 区分度 为 2 / count(*);

11. 索引失效有那些

左模糊查询 like %xx， 使用函数，使用表达式计算，

不遵循最左匹配原则

在or前是索引列，or后不是索引列，会失效

12. 如果一个列既是单列索引，也是联合索引，单独查它的话先走哪个

这要比较这两种不同走法，他们两个的查询成本那个更低。

13. 怎么决定建立那些索引

  1. 什么时候适用索引

    字段有唯一性限制的、经常用于where，group by， order by的字段、

  2. 什么时候不适合建立索引

    数据量少的、不经常用于where，group by， order by的字段、字段中存在大量重复值的、经常更新的字段。

14. 索引优化详细讲讲

  1. 在一些使用大字符串作为索引的情况下，我们可以使用前缀索引来减小索引的大小

  2. 在查找数据时，多使用覆盖索引优化。

  3. 主键索引最好是自增的，

  4. 防止索引失效

    避免使用左模糊查找，函数，表达式计算等、

    遵循最左匹配原则

    避免or前后列属性有非索引列。这样就能保证索引不会失效。

4. 事务

1. 事务的特性是什么

acid 原子性 一致性 隔离性 持久性

持久性是通过redo log(重做日志)来保证的；
原子性是通过undo log(回滚日志)来保证的；
隔离性是通过MVCC(多版本并发控制)或锁机制来保证的；
一致性则是通过持久性+原子性+隔离性来保证；

2. mysql可能出现什么和并发相关的问题

脏读：一个事务读到了一个未提交事务修改过的数据。

不可重复读：一个事务内多次读取同一数据，出现前后读到的数据不一致

幻读：一个事务内多次查询某个符合查询条件的记录数量，出现前后两次查询到的数量不一致

3. mysql是怎么解决并发问题的

锁机制

事务隔离级别

MVCC：Mysql使用MVCC来管理并发访问，它通过在数据库中保存不同版本的数据来实现不同事务之间的隔离。在读取数据时，mysql会根据事务的隔离级别来选择合适的数据版本，从
而保证数据的一致性。

4. 事务的隔离级别有那些

读未提交：指一个事务所做的修改能够被其他事务看到

读提交：指一个事务所做的修改只有在事务提交之后才能被其他事务看到

可重复读：指一个事务在为提交之前所看到的数据和开启此事务时所看到的数据是一样的。

串行化：会对记录上读写锁，当发生读写冲突时，后访问的事务必须等待前一个事务执行完成，才能继续执行。

5. 举个例子说可重复读下的幻读问题

事务A首先查询表中id为1的一条记录，（此时表中没有这条id为1的记录）返回空，然后事务B插入一条id为1的记录提交。然后事务A取更新这条id为1的记录，然后查询这条id为1的记录会有这条记录的结果。

6. mysql设置了可重复读隔离级别，怎么保证不发生幻读

可以在开启事务之后，立马执行select…for update语句，这样就会对记录加上next-key lock。

7. 串行化隔离级别是通过什么实现的？

通过行级锁实现的。串行化隔离级别下，普通的select查询是会对记录加S型的next-key锁

8. 一条update是不是原子性的？为什么？

是原子性，主要通过锁+undolog 日志保证原子性的

在执行update操作时，会对该行加上行级锁，防止其他事务修改这条记录。如果事务执行失败，会通过undo log进行回滚。

5. 锁

1. 讲一下mysql里有哪些锁？

有全局锁，表级锁，行锁三类

2. MySQL两个线程的update语句同时处理一条数据，会不会有阻塞？

会，因为更新语句会对记录加上行级锁，当一个事务拿到了这个记录的行级锁，另一个事务就会阻塞

3. 两条update语句处理一张表的不同的主键范围的记录，一个<10，一个>15，会不会遇到阻塞？底层是为什么的？

不会，因为锁住的范围不一样。一个锁住的是（-∞，10），一个锁住的是（15， +∞）；

4. 如果2个update范围都没用到主键或索引？还会阻塞吗？

如果updata语句没使用索引，那么就会触发全表扫描。于是就会对全表的每个行加上行级锁，所以会阻塞。

6. 日志

1. 日志文件是分成了哪几种？

redolog重做日志：实现事务的持久性，用于断电恢复

undolog回滚日志：实现事务的原子性，用于实现事务回滚和mvcc

binlog二进制日志：用于数据备份和主从复制

relaylog中继日志：slave通过io线程复制master的binlog日志生成的日志

慢查询日志：记录执行时间较长的sql

2. 讲一下binlog

binlog保存的是全量的日志，用于数据备份和主从复制

在执行更新操作时，会产生binlog，等事务提交之后，会将binlog写入到binlog日志文件中，binlog不会记录查询类的操作。

3. undo日志的作用

用于实现事务回滚。比如在进行删除操作时，在undolog日志中把这条记录全都记下来，然后进行回滚操作时，执行相反的操作即insert操作。

4. 有了undolog为啥还需要redolog呢？

redo log 记录了此次事务「完成后」的数据状态，记录的是更新之后的值；

undo log 记录了此次事务「开始前」的数据状态，记录的是更新之前的值；

事务提交之前发生了崩溃，重启后会通过 undo log 回滚事务，事务提交之后发生了崩溃，重启后会通过 redo log 恢复事务

7. 性能调优

1. mysql的explain有什么作用？

explain是查看sql的执行计划。比如有没有用索引，有没有涉及到索引覆盖等；

3. 如果Explain用到的索引不正确的话，有什么办法干预吗？

可以使用 force index，强制走索引。

8. 架构

1. MySQL主从复制了解吗

mysql主从复制主要依赖于binlog，也就是将mysql上所有的变化都以二进制的形式存储在磁盘上。复制的过程其实就是将主库上的binlog日志复制到从库上

2. 主从延迟都有什么处理方法？

强制走主库方案

3. 分表和分库是什么？有什么区别？

分库 是将一个数据库拆分 成多个独立的数据库，每个数据库保存部分原来的数据，这样就能减缓单机mysql下的性能瓶颈问题

分表 是将一个数据量较大的表垂直拆分成多个小表，这样能解决单个表数据量过大问题
